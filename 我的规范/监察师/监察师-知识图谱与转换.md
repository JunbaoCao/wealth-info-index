# 🕸️ 监察师 · 知识图谱、流程备份与格式转换框架

> 你要求的"流程弄成 RAG 的知识图谱、md 文件有流程备份、md 到 js 的转换、确保机器了解清楚"——这里是完整设计。
> 主索引：[[监察师]] · 后台守护见 [[监察师-后台守护与自愈]] · 设备档案见 [[我的数据/我的电脑/设备档案]]

## 一、整体思路（三层体系）

把监察师的能力做成**三层**，从原始数据到可查询的知识：

```
[第1层] 原始数据层 ── 设备档案.md、日志、上传的文件
        ↓
[第2层] 流程备份层 ── 每次操作/处理流程都留档成 md（可回溯、可复现）
        ↓
[第3层] 知识图谱层 ── 把档案和备份向量化，变成可检索的 RAG 知识库
```

**这就是你想要的"清清楚楚、可回溯、可查询"的设备知识体系。**

## 三、第2层：流程备份层（可回溯）

**目标：每个处理流程都留下 md 备份，随时能复现、能回查。**

### 流程备份规范
每次处理（转换文件、诊断问题、更新档案）都记录成一份 md：

```
监察师\_运行时\流程备份\YYYY-MM-DD-编号-动作名称.md
```
内容固定结构：
```markdown
# 流程备份：<动作名称>
- 时间：YYYY-MM-DD HH:MM:SS
- 动作：<做了什么>
- 输入：<文件路径/数据>
- 输出：<结果路径/结论>
- 验证：<怎么验证它对了>
- 备注：<异常/注意点>
```

### 备份目录结构建议
```
监察师/
├── 设备档案.md
└── _运行时/               ← 运行时自动生成的目录
    ├── 日志/               ← 心跳+操作
    ├── 流程备份/           ← 每次处理留档
    │   └── YYYY-MM-DD-*.md
    ├── 上传文件/           ← 用户上传的原件
    └── 知识库/             ← RAG 向量化结果（第3层）
```

## 四、第3层：知识图谱 / RAG 层（可查询）

**目标：把档案+备份向量化，变成可检索的知识图谱，让任何会话/智能体都能"查"到设备情况。**

### RAG 落地方案（用你现有的工具，不额外装东西）

| 步骤 | 做什么 | 用什么 |
|------|--------|--------|
| 1. 汇总 | 把设备档案+流程备份合并成文本块 | `fs` 读取全部 md |
| 2. 分块 | 按标题/段落切块，每块带来源路径 | Python 脚本 |
| 3. 向量化 | 把文本块转成向量（embedding） | Cherry 的 `qwen3-embedding` 模型（已装） |
| 4. 存储 | 向量+原文存进知识库 | `storage`/`storageDomain` 或文件 |
| 5. 检索 | 提问时先向量检索，再让 AI 基于结果回答 | `llm` + `storage` |

### 知识图谱形态
- 每份档案/备份 = 一个节点
- 相互引用（`[[双链]]`）= 节点关系
- Obsidian 的图谱视图天然就是知识图谱可视化

> 💡 你的 Obsidian 已经支持双链图谱——把文件都互相链好（前面已经做了），图谱视图里就是一张知识网络。

## 五、格式转换层（md / json / js / python 互转）

**你要求"md 到 js 的转换"和"上传各种格式"。** 这是转换框架：

### 转换工具映射（用你已装的运行时，零新装）
| 从 → 到 | 用什么 | 示例命令 |
|---------|--------|----------|
| md → js/ts | Node.js | 用脚本把 md 转成 JS 字符串/对象 |
| md → python | Python | 读 md，转成 Python 数据结构 |
| md → json | Node/Python | `JSON.stringify` 或 `json.dumps` |
| json/js → md | Node/Python | 反向，把对象格式化回 md |
| 任意 → 文本 | `rg`/Python | 提取纯文本 |
| PDF/Office → 文本 | MinerU / Python | MinerU 解析 PDF，Python 读 Office |

### 转换流程（标准做法）
1. 后台守护收到文件 → 存进 `上传文件\`
2. 用对应转换器处理 → 输出到 `转换结果\`
3. 写流程备份 md（记录输入输出）→ 存进 `流程备份\`
4. 把结果文本向量化 → 进知识库

### 保证"机器了解清楚"的关键
每次转换**都留一份流程备份**，记录：输入文件、用的命令、输出格式、验证结果。这样**任何一次转换都能回查、能复现、能验证对错**——这就是"确保机器了解是清楚的"。
