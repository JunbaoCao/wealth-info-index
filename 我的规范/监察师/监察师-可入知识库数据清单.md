## 三、各类型文件数量盘点（决定要不要入RAG）

| 类型 | 数量 | 是否入RAG |
|------|------|-----------|
| `.md` | 285 (D盘) + 3897 (E盘) | ✅ 文本，最适合 |
| `.doc` | 3654 | ⚠️ 需先转文本/OCR |
| `.docx` | 549 | ✅ 可转文本 |
| `.xls` | 6195 | ⚠️ 结构化表格，需解析 |
| `.xlsx` | 2100 | ⚠️ 同上 |
| `.pdf` | 727 | ⚠️ 需OCR（你有pp-ocrv6） |
| `.txt` | 1216 | ✅ 纯文本，直接入 |
| `.csv` | 29 | ✅ 表格，易解析 |
| `.json` | 899 | ✅ 结构化，可直接入 |

> 结论：**文本类（md/txt/json）最易入RAG**；**表格类（xls/xlsx/csv）需解析成文本**；**扫描类（pdf/doc图片）需先用 pp-ocrv6 OCR 转文字**。

## 四、落地建议（怎么用这份清单）

### 方式A：最省事（推荐先做）
1. 在 Cherry Studio 知识库界面，把 `D:\wealth基础数据\wealth数据资产\20260808之前数据` 这个文件夹拖进去新建一个知识库。
2. 用 qwen3-embedding（本地）或硅基流动 embedding 建索引。
3. 提问时勾选这个库 → AI 基于你的审计报表回答。

### 方式B：自动化（配合后台守护）
- 后台守护插件按需调用 Python 脚本，把新增文件自动向量化进知识库。

### 方式C：按项目隔离
- 给每个审计项目（乡宁、通合煤业、台头煤焦、丰裕粮油…）各建一个知识库，问题更聚焦。

## 五、隐私提醒（监察师底线）

- `wealth数据资产` 里的审计报告、财务数据涉及客户商业机密，**建议只入本地/私有知识库，不要上传到任何公开仓库或云端RAG**。
- 你的 `监察师-template` 仓库（GitHub 公开）里**不含任何业务数据**，只含工具和方法，可以安全公开。
- 硅基流动（云端RAG）会传向量，不含原文——但仍建议敏感数据用本地 qwen 嵌入，更安全。
