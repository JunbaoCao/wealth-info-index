## 一、先懂编码类型（别搞混）

| 编码类型 | 是什么 | 特点 | 什么时候用 |
|----------|--------|------|-----------|
| **UTF-8（无 BOM）** | 现代通用编码 | 兼容 ASCII、体积小、跨平台 | ✅ **源码、网页、配置文件首选** |
| **UTF-8 BOM** | UTF-8 带文件头标记 | 文件开头有 EF BB BF | 部分 Windows 工具识别用，通常可避免 |
| **ANSI/GBK (936)** | 中文 Windows 传统编码 | 中文占 2 字节、不跨平台 | ⚠️ 老记事本 ANSI 文件、老程序 |
| **UTF-16/LE** | Windows 原生编码 | 每个字符 2 字节 | Windows 系统内部、部分配置 |

> 💡 **记住结论**：你写**新代码一律用 UTF-8 无 BOM**。只有**老文件（记事本 ANSI 存的）**才是 GBK。

## 二、这台电脑的实测编码值（已核实）

| 项目 | 实测值 | 说明 |
|------|--------|------|
| Windows 代码页 ACP | **936 (GBK/GB2312)** | 系统级 ANSI 代码页 |
| Windows 代码页 OEMCP | **936** | 控制台旧代码页 |
| PowerShell 输出编码 | **UTF-8** | 控制台输出中文正常 |
| PowerShell 输入编码 | **UTF-8** | 控制台输入中文正常 |
| Python 默认编码 | **UTF-8** | `sys.getdefaultencoding()` = utf-8 |
| Python 文件系统编码 | **UTF-8** | `sys.getfilesystemencoding()` = utf-8 |
| Node.js 编码 | **UTF-8** | 默认即 UTF-8 |
| 文件存储规范 | **LF + 末尾换行** | DSH 仓库 `.editorconfig`/`.gitattributes` 强制 |

> ✅ **结论：你所有核心工具的默认编码都是 UTF-8，中文/Emoji 都不会乱码。**
> ⚠️ 唯一要注意的：系统级代码页是 936(GBK)，这影响**旧的记事本 ANSI 文件**和**老程序**，不影响 VS Code/Node/Python。

## 三、换行符规范（LF vs CRLF）

| 文件类型 | 规范 | 依据 |
|----------|------|------|
| Git 仓库源码（DSH） | **LF** + 末尾换行 | `.gitattributes`：`* text=auto eol=lf` |
| 编辑器写入 | **LF** + 末尾换行 | `.editorconfig`：`end_of_line = lf` + `insert_final_newline = true` |
| Windows 批处理 `.bat/.cmd` | **CRLF**（特例） | cmd.exe 需要 CRLF |
| Excel/CSV 文本 | 通常 CRLF | 视工具而定 |

> ✅ **代码文件一律 LF 换行**。你的 VS Code 已设 `files.insertFinalNewline: true` 自动补末尾空行。

**DSH 仓库证据**（`E:\dsh-workspace\deepseek-harness\.editorconfig`）：
```
[*]
end_of_line = lf
insert_final_newline = true
```
（`.gitattributes` 还写死 `* text=auto eol=lf`，保证任何机器 checkout 都是 LF。）

## 五、写代码时的格式规范（监察师必守）

1. **一律 UTF-8 无 BOM** 保存源码（VS Code 默认，别改 ANSI/GBK）。
2. **换行 LF**（`.bat`/`.cmd` 例外用 CRLF）。
3. **末尾有空行**（`files.insertFinalNewline` 已自动做）。
4. **半角写代码、全角写注释/文档**，别混用。
5. **中文路径用 PowerShell**（已 UTF-8），别用老 cmd。
6. **CSV/Excel 文件**：VS Code 已配 Rainbow CSV + 大列宽（1024）自动换行，读大表不串行。

## 六、乱码排查手册（遇到乱码怎么办）

| 现象 | 原因 | 解决办法 |
|------|------|----------|
| 中文变 `鏇瑰啗` / `鈥?` 这种乱码 | **UTF-8 文件被当成 GBK 读**（或反之） | 用 VS Code 打开，右下角编码 → 选 UTF-8 或 通过"重新打开编码"切换 |
| 中文变 `锟斤拷` | **GBK 文件被当 UTF-8 读** | 右下角编码 → 选择 通过"GBK/ANSI" 重新打开 |
| PowerShell 里中文乱码 | 控制台编码不是 UTF-8 | 先运行 `[Console]::OutputEncoding=[Text.UTF8Encoding]::new($true)` 或 `chcp 65001` |
| Python 读文件中文乱码 | 没指定编码 | `open(f, encoding='utf-8')` 或 `encoding='gbk'`（老文件） |
| Node 读文件中文乱码 | 没指定编码 | `fs.readFileSync(f,'utf8')` |

**通用解决思路**：先确认文件**实际编码**，再用**相同编码去读/存**。VS Code 右下角能看和改。

## 七、自查命令（随时验证，一个都别错）

```powershell
# 语言区域
Get-Culture
# 时区
Get-TimeZone
# 控制台编码
[Console]::OutputEncoding.WebName
# Python 编码
python -c "import sys; print(sys.getdefaultencoding(), sys.getfilesystemencoding())"
# Node 版本
node --version
# Git 换行
git config --get core.autocrlf
# 看当前文件编码（PowerShell）
Get-Content '文件路径' -Encoding Byte | Select-Object -First 4   # 看前4字节判断BOM
```
