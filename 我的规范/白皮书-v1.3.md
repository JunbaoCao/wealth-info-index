# 威尔思·一人公司数据与 AI 协作白皮书 v1.3

> 一句话定位：这是一人事务所（威尔思）的[数据怎么放、AI 怎么干活、人怎么看全貌]的单一权威文档。
> v1.3 相对 v1.2 的核心变化：新增 Obsidian 作为人类视角索引层，并把零散规则收敛成[数据-工具-工作流-约束]四层。

## 0. 本文约定（必读）

- 本白皮书是唯一真源（source of truth）。任何 Agent（含未来的我）开工前必须读它。
- 面向两类读者：机器（Agent/脚本）遵守机器约束（§5）；人（曹军豹）遵守人的行动规范（§6）。
- 版本升级：本文只在 我的规范 白皮书-v1.3.md 维护；旧版本保留作历史，不回改。

## 1. 本机真实数据架构（已核对）

本机关键分层：
- C盘 = 系统 + 用户配置（不碰）
- D: wealth基础数据 = 财富数据总根（用户私有）
  - wealth数据资产 = 原始数据根，只读，绝不改
  - cherry工作目录 = AI 资产根，Agent 可写
  - Obsidian知识库 = 人类索引层，本知识库
- E: dsh-workspace = 开发/DSH 工作区（0814 是本 Agent 沙盒 + 本知识库）
- F盘 = U盘，只读参考，绝不动

所有权边界（铁律）：

| 层 | 谁负责 | 写入 | 删除 |
|----|--------|------|------|
| wealth数据资产 | 只人 | Agent 只读 | Agent 绝不删/移 |
| cherry工作目录 | Agent+人 | Agent 可写 | 走 git，不硬删 |
| Obsidian知识库 | 人 | 人写索引 | 人维护 |
| F盘（U盘） | 人 | 只读 | 人，且默认不动 |

## 3. 三大体系的分工

| 体系 | 工具 | 谁看 | 作用 |
|------|------|------|------|
| 原始数据 | 文件夹 | 人 | 账套/凭证/扫描件，只读 |
| AI 协作 | Cherry Studio + 白皮书 | AI | 写报告、整理账套、沉淀经验 |
| 人类索引 | Obsidian（本库） | 人 | 全局搜索、双向链接、看懂全貌 |
| 对外交付 | 飞书 / Word | 客户 | 文档、报告成品 |

核心思想：Obsidian 不搬文件，只做索引+链接。文件留在原处，用 [[链接]] 和外部链接看见它们。

## 4. Obsidian 知识中枢使用规范

### 4.1 本库目录（对应你的概念）
| 目录 | 装什么 |
|------|--------|
| 我的数据 | 各盘文件在哪（wealth 引用、乡宁、报告文书、工具） |

1. 今天做了什么 → 在 我的工作 工作日志.md 记一行
2. 新增了什么文件 → 在对应 我的数据 索引里补一行链接
3. 学到/沉淀了什么 → 在 我的知识 加一条，或写前人经验

## 5. 机器约束（给 Agent 的硬规则）

任何 Agent（含未来的我）在本机工作，必须遵守以下规则，违反即视为失效。

### 5.1 权限红线
1. D: wealth基础数据 下 wealth数据资产 只读，绝不修改/删除/移动。
2. F盘（U盘）只读参考，绝不动任何文件。
3. C: Windows、C: Program Files 等系统目录不碰。
4. E: dsh-workspace 0814 是唯一可自由读写区（本 Agent 沙盒 + 本知识库）。
5. 其他盘（C/D/E）根目录文件只读，如需写入必须先向人申请。

### 5.2 工作流约束
1. 开工先读本白皮书 + 最新前人经验（cherry工作目录 前人经验 最近 3 份）。
2. AI 产出只写工作区（cherry工作目录 日期 04-产出-output），不污染原始数据根。
3. 报告永远写在工作区，不写在 wealth数据资产。
4. 报告里引用数据源路径（每个结论来自哪个文件）。
5. 不删已定稿报告（v1.0+）；不代签、不发邮件、不承诺客户。

### 5.3 文件名机器硬约束
无空格、无中文标点、日期 YYYYMMDD、版本 -vX.Y、不覆盖。

## 6. 人的行动规范（曹军豹）

1. 每天维护一次 我的工作 工作日志.md（做了什么、决策、下一步）。
2. 原始数据永远是源头，Obsidian 只是索引——改文件去原处，别在库内改。
3. 新工作区按 cherry工作目录 日期 建，标准结构见 v1.2 §5.3。
4. 沉淀：每次有价值的对话/决策，写进前人经验。
5. 版本意识：报告初稿 v1.0 → 你审 → v1.1 → 定稿，用版本号，不用最终。
