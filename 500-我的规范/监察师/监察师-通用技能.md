# 🕵️ 监察师 · 电脑架构监察通用技能（Skill）

> 一份**泛式 skill**：不依赖具体电脑，照着这个清单问问题、查环境、摸语言、查编码，就能系统掌握任何一台电脑的架构。
> 返回：[[我的电脑-索引]] · [[监察师]]

---

## 这是什么

这是一个可复用的"电脑监察"方法论。它的作用是：**到一台新电脑上，我该问哪些问题、查哪些地方，才能把它的系统、硬件、语言、格式、编码、工具链彻底摸清。**

**适用场景**：换电脑、装新环境、排查编码问题、接手一台不熟悉的机器、写环境文档。

## 一、摸底顺序（按这个顺序问/查，最省事）

### 第 1 步：系统是什么
| 要问/查的 | 用什么查 | 看什么 |
|-----------|----------|--------|
| 操作系统品牌 | 系统设置/关于 | Windows / macOS / Linux |
| 系统版本/构建号 | 注册表 `HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion` | CurrentBuild、DisplayVersion |
| 架构位数 | `$env:PROCESSOR_ARCHITECTURE` | x64 / arm64 |
| 安装类型 | 同上 | Client / Server |

> ⚠️ 注意：Win11 24H2+ 的 ProductName 可能显示 "Windows 10"，要看构建号（26xxx=Win11）判断。

### 第 2 步：硬件配置
| 要查的 | 用什么查 |
|--------|----------|
| CPU | 注册表 `HKLM\HARDWARE\DESCRIPTION\System\CentralProcessor\0` 的 ProcessorNameString |
| 显卡 | `HKLM\SYSTEM\CurrentControlSet\Control\Class\{4d36e968-...}` 的 DriverDesc |
| 网卡 | `HKLM\SYSTEM\CurrentControlSet\Control\Class\{4d36e972-...}` 的 DriverDesc |
| 内存 | 任务管理器 → 性能 → 内存（或需管理员权限的 WMI） |
| 磁盘 | `.NET DriveInfo::GetDrives()` 或 `Get-PSDrive` |

> ⚠️ 内存/型号常需管理员权限，普通权限查不到就标"待手动确认"。

### 第 3 步：编程语言/运行时（核心）
对每种语言逐个问：
- **装没装**：`<工具> --version`
- **装在哪**：`Get-Command <工具>` 看 Source
- **包管理器**：npm/pip/pnpm/bun/uv 的版本
- **有无版本管理器**：nvm/volta/py

| 常见工具检查命令 |
|------------------|
| `node --version` / `npm --version` |
| `python --version` / `pip --version` / `py -0` |
| `git --version` |
| `bun --version` / `uv --version` / `mise --version` / `rg --version` |
| `pnpm --version` |

### 第 4 步：编码与格式（最容易出错，必查）
| 要查的 | 用什么查 | 标准值 |
|--------|----------|--------|
| 系统 UI 语言 | `Get-Culture` | zh-CN / en-US... |
| 时区 | `Get-TimeZone` | UTC+8 / UTC... |
| Windows 代码页 | `HKLM\...\Nls\CodePage` 的 ACP/OEMCP | 936=GBK, 65001=UTF8 |
| 控制台编码 | `[Console]::OutputEncoding.WebName` | utf-8 最佳 |
| Python 编码 | `python -c "import sys; print(sys.getdefaultencoding())"` | utf-8 最佳 |
| 文件换行 | 看仓库 `.editorconfig` / `.gitattributes` | LF 最佳（.bat 用 CRLF） |

### 第 5 步：工具链/生态
- 编辑器：VS Code 版本、界面语言、用户 settings.json 里的编码/换行设置
- 包管理：npm 全局目录、pnpm store 位置
- 是否有专用工具链目录（如 Cherry 的 `.cherrystudio\bin`）

### 第 6 步：数据盘点（判断哪些资料入RAG）
扫描本机各盘，按优先级判断哪些资料适合入知识库（RAG）：
1. **核心业务数据**（如 wealth 数据资产）→ 最优先
2. **工作方法沉淀**（AI对话记录、skill库、白皮书）→ 第二
3. **专项项目资料**（如乡宁国企审计）→ 第三
4. **环境档案**（设备档案等本地Obsidian）→ 已在本地，随查随用
5. **普通用户目录**（Documents/OneDrive）→ 基本为空，暂不处理

> 详见 `docs/知识图谱与RAG.md` 的"数据清单"部分。

### 每个语言/工具的标准提问清单（对照问，一个不漏）

**Node.js / JS**
- [ ] 版本？(`node --version`)
- [ ] 路径？(`Get-Command node` → Source)
- [ ] npm/npx 版本？(`npm --version`)
- [ ] 全局包目录？(`npm root -g`)
- [ ] 装没装版本管理器？(`nvm`/`volta`/`fnm`)

**Python**
- [ ] 版本？(`python --version`)
- [ ] 路径？(`Get-Command python` → Source)
- [ ] pip 版本？(`pip --version`)
- [ ] 有几个版本？(`py -0`)
- [ ] 默认编码？(`python -c "import sys;print(sys.getdefaultencoding())"`)

**Git**
- [ ] 版本？(`git --version`)
- [ ] 路径？(`Get-Command git` → Source)
- [ ] 换行配置？(`git config --get core.autocrlf`)

**包管理器**
- [ ] pnpm 版本？(`pnpm --version`)  store 在哪？
- [ ] bun/uv/mise/rg 有没有？在专用工具链目录？(`.cherrystudio\bin`)

**编辑器**
- [ ] 版本？(`code --version`)
- [ ] 界面语言？(settings.json 里 `locale`)
- [ ] 编码/换行设置？(settings.json 里 `files.insertFinalNewline`、`.editorconfig`)

## 常见环境问题排查决策树（照树走）

```
代码/文件中文乱码？
├─ 是 → 文件编码与读取编码不一致
│    ├─ 用 VS Code 打开 → 右下角看编码 → 切换 UTF-8/GBK 重开
│    └─ 或用命令检测：Get-Content -Encoding Byte 看开头 EF BB BF(BOM UTF-8)
├─ 否
└─ 命令跑不起来 / 提示"不是内部或外部命令"
     ├─ 工具没装 → 装对应运行时
     └─ 装了但 PATH 没有 → 用完整路径或重装勾选"加入 PATH"
```

## 二、总结成文（输出模板）

摸完后，建议整理成这样的档案结构（可复制到 Obsidian）：

```
📁 电脑档案/
├── 01-系统.md      ← 系统、版本、架构、硬件
├── 02-语言运行时.md ← 每种语言的版本+路径+包管理器
├── 03-格式编码.md   ← UTF-8/换行/时区/区域 + 自查命令
├── 04-工具链.md    ← 编辑器、包管理、专用工具链
└── 00-索引.md      ← 总览速查表
```

## 三、监察师自检清单（每台电脑必答）

- [ ] 操作系统是什么？版本/构建号多少？32 还是 64 位？
- [ ] CPU / 显卡 / 网卡 / 内存 / 磁盘各是什么？
- [ ] 装了 Node/Python/Git 吗？各自版本和路径？
- [ ] 包管理器（npm/pip/pnpm/bun/uv）版本？
- [ ] 系统语言、时区、代码页各是什么？
- [ ] 控制台/Python 默认编码是不是 UTF-8？
- [ ] 代码文件换行是 LF 还是 CRLF？编辑器怎么设置？
- [ ] 有没有专用工具链目录（.cherrystudio、.dsh 等）？

---

## 四、如何在别的电脑上用它

1. 把这份文档拷过去（或同步到新电脑的 Obsidian）。
2. 按"摸底顺序"逐项执行，把结果填进对应档案。
3. 遇到查不到/需权限的，标"待手动确认"并给出查看方法。
4. 最后用"自检清单"复核是否漏项。
