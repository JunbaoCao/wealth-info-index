### 🧱 第二步：处理"重复 skill/mcp"的真相

**实际上你的 skill 并不重复**：
- Cherry 的技能（4个）＝ **用户日常助手类**（搜索、找技能、建技能、Cherry工具）
- DSH 的技能（11个）＝ **开发/代码类**（code review、文档、翻译…）

**结论**：不需要删掉任何一边，而是**互补**。你在 Cherry 里正常用你的日常技能，我在 DSH 里用我的开发技能，两边通过 [[共享资源索引]] 互相知道对方有什么即可。

> ⚠️ 唯一要"整理"的：如果某个技能两边都有重复功能（比如都有"联网搜索"），保留功能更强或你更常用的那个，另一个在索引里标注"备用"即可。**不要物理删文件**，先标注再决定。

### 🧱 第三步：在 Cherry Studio 里新建/完善你的智能体

你已经有主智能体 **曹军宝**（`62843a8e-...`，有 SOUL.md+USER.md）。
你还有一个**空壳**智能体 `0091a7af-...`（SOUL.md/USER.md 是空的）。

**操作建议**：
1. **完善主智能体 曹军宝**：打开 Cherry Studio → 智能体/Agent 列表 → 找到"曹军宝"，把 SOUL.md（人格）和 USER.md（你的信息）补充完整。
2. **处理空壳 `0091a7af`**：要么删除它，要么给它一个明确用途（比如"工作专用"或"私人专用"）。
3. **新建一个"工作区智能体"**（如果你想要分开）：在 Cherry Studio 里新建 Agent，新建时它会生成一个 GUID 文件夹，你在里面写 SOUL.md + USER.md 定义用途。

> 📌 **关键点**：Cherry Studio 里每个智能体 = `Data\Agents\<GUID>\` 一个文件夹，里面放 `SOUL.md`（人格）+ `USER.md`（用户信息）+ 可选的 `knowledge` 等。**新建智能体就是新建一个带 SOUL.md 的文件夹**。

### 🧱 第四步：规划"不同工作区"

"工作区"在两个软件里含义不同，要分别处理：

#### 🔹 Cherry Studio 的工作区
- Cherry 用 `Data\Projects\`（我看到 `.claude\projects\D--wealth-----cherry-----0809` 这种）按**项目目录**分隔会话。
- 你已有工作区：`D--wealth-----cherry-----0809`（看起来是 wealth 相关项目）。
- **做法**：每个项目/工作区 = 一个项目文件夹。想开新工作区，就在 Cherry 里"打开新项目"并指向对应目录。

#### 🔹 DeepSeek Harness 的工作区
- DSH 用工作区目录（`E:\dsh-workspace\0814` 这种）区分，每个目录是一个独立工作区。
- 我（当前智能体）跑在 `E:\dsh-workspace\0814` 工作区。
- **做法**：每个项目开一个 `E:\dsh-workspace\<项目名>` 目录，就是独立工作区。

> 📌 **结论**：Cherry 用项目目录分工作区，DSH 用文件夹分工作区，**思路一样、落点不同**。你在索引的 `04-映射对照.md` 里记好"这个工作区在 Cherry 对应哪个项目目录、在 DSH 对应哪个文件夹"即可。

### 🧱 第五步：把技能/skill 做成"两边都能看"

因为格式相同（都是 SKILL.md），你可以**做软链接或复制**，让一个技能在两边的 skill 目录里都能出现：

**方法A（推荐，软链接，省空间）**：
```
# 在 Cherry 的技能目录里，链接到共享技能库
New-Item -ItemType SymbolicLink -Path "C:\Users\HP\AppData\Roaming\CherryStudio\Data\Skills\my-shared-skill" -Target "E:\dsh-workspace\shared-skills\my-shared-skill"
# DSH 同理链接
New-Item -ItemType SymbolicLink -Path "E:\dsh-workspace\deepseek-harness\.agents\skills\my-shared-skill" -Target "E:\dsh-workspace\shared-skills\my-shared-skill"
```

**方法B（简单，复制）**：把技能文件夹复制到两边的 skill 目录。缺点是改一处不同步。

> 📌 建议：先建一个 `E:\dsh-workspace\shared-skills\` 作为"技能源"，两边都用软链接指向它——这就是你想要的"**一个文件夹两个都能用**"的现实落地方案。
