# 📁 共享资源索引

> 一套**逻辑上的共享资源库**，把 DeepSeek Harness 和 Cherry Studio 两边的能力都登记在这里，两个工具都指向它来对照、复用。
> 返回：[[我的电脑-索引]] · 深入对比见 [[工具对比（DeepSeek Harness vs Cherry Studio）]]

---

## 为什么要有这个文件夹？

你说"有些重复的 skill 还有 mcp，想要一个文件夹两个都能用"。

**关键事实**：两个软件**物理上不能共用一个文件夹**——它们的配置路径、文件格式、运行机制都不同（一个在 `E:\dsh-workspace\deepseek-harness`，一个在 `C:\Users\HP\AppData\Roaming\CherryStudio`）。强行放一个文件夹里，两边都识别不了。

**所以我的方案是"逻辑共享"**：建这个索引文件夹，里面放**注册表 + 说明**，让两套软件都"知道"对方有什么、自己能用什么、怎么对应。这样你只需要维护这一个文件夹，就管住了两边的资源。

---

## 目录结构（建议这样组织这个共享库）

```
共享资源索引/
├── 00-总览.md              ← 本文件，入口
├── 01-Skills/              ← 两边技能对照表
│   ├── cherry-skills.md     ← Cherry Studio 的技能清单
│   └── dsh-skills.md        ← DeepSeek Harness 的技能清单
├── 02-Agents/              ← 两边智能体对照表
│   ├── cherry-agents.md     ← Cherry Studio 的智能体（曹军宝等）
│   └── dsh-presets.md       ← DeepSeek Harness 的预设（cordis/code...）
├── 03-MCP/                 ← 两边的工具/插件对照
│   ├── cherry-mcp.md        ← Cherry 内置3个MCP服务
│   └── dsh-plugins.md       ← DSH 的 Cordis 插件/MCP provider
├── 04-映射对照.md           ← 关键：一份"这个功能在那边对应什么"的速查表
└── README.md               ← 给未来智能体/自己看的说明
```

## 关键映射对照（"这个在那边是什么"）

| 你想做的事 | 在 Cherry Studio | 在 DeepSeek Harness |
|-----------|----------------|--------------------|
| 给 AI 一个"技能" | 在 `Data\Skills\` 建文件夹+SKILL.md | 在 `.agents\skills\` 建文件夹+SKILL.md |
| 定义一个"智能体/人设" | 在 `Data\Agents\<GUID>\SOUL.md` 写人格 | 用 `cordis.yml` 预设声明 |
| 接入一个工具服务 | 用内置 MCP 服务 | 用 Cordis 插件或 MCP provider |
| 给 AI 记忆 | 知识库 + agent-memory | 会话存储 `.dsh\sessions` |

---

## 怎么用这个文件夹

1. **维护**：以后新增 skill / agent / mcp，就到对应分类文件里登记一条。
2. **给智能体看**：把 `00-总览.md` 的链接放进两边的智能体说明里，让它们启动时读这个索引，就知道"全局有哪些能力可用"。
3. **对齐**：想做某个功能时，先查 `04-映射对照.md`，看该在 Cherry 配还是 DSH 配。
